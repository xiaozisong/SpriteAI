# 项目开发规则

## 1. 基本原则

你正在以高级软件工程师的身份维护当前代码仓库。

在修改任何代码之前：

1. 先理解现有实现。

2. 搜索相关组件、工具函数、类型、API、Service 和已有设计模式。

3. 优先复用现有抽象，而不是重新创建类似实现。

4. 避免与当前需求无关的重构。

5. 使用能够解决问题的最小修改方案。

不要修改与当前任务无关的文件。

除非确有必要，否则不要添加新的第三方依赖。

---

## 2. 代码质量

所有代码都应该达到可用于生产环境的质量。

代码应该具备：

- 可读性

- 可维护性

- 类型安全

- 模块化

- 可测试性

- 与现有代码风格一致

避免：

- 重复逻辑

- 不必要的抽象

- 过深的条件嵌套

- 魔法数字

- 滥用 `any`

- 无效代码

- 被注释掉但未删除的废弃代码

- 过早优化

优先选择简单、清晰、容易理解的实现，而不是过度复杂或炫技的实现。

---

## 3. TypeScript

严格使用 TypeScript。

规则：

- 除非确实无法避免，否则禁止使用 `any`

- 优先使用 `unknown` 代替 `any`

- API 返回值必须有明确类型

- 优先复用已有 interface 和 type

- 避免不必要的类型断言

- 简单局部变量优先使用类型推导

- 只有确实需要跨模块复用的类型才进行 export

const data: any = await fetchData();
