## 1. 项目背景

独立游戏团队、Game Jam 创作者、游戏美术外包团队和教育场景中的开发者，经常需要快速产出角色精灵、动作序列、图标、道具和场景切片素材。传统生产链路依赖手工绘制、频繁沟通和多轮返工，素材风格一致性、动作连续性和导出规格也较难保证。

本项目目标是实现一款生成 2D 游戏素材的 Agent 产品，让用户用自然语言描述素材需求，Agent 自动拆解为素材规格、生成计划、图像生成任务、迭代建议和可导出资源包，最终得到可直接进入游戏开发流程的 2D 素材。

## 2. 产品定位

**一句话定位**：面向游戏创作者的 AI 2D 游戏素材生成 Agent。

**核心价值**：

- 将“文字描述”转化为可用的 2D 游戏素材。
- 将单张图生成扩展为角色、动作序列、道具、场景等成组资产生成。
- 通过 Agent 规划、校验和迭代，降低提示词门槛并提升素材一致性。
- 支持导出透明 PNG、Sprite Sheet、JSON 元数据等游戏工程常用格式。

## 3. 目标用户

| 用户类型 | 典型诉求 | 产品价值 |
|---|---|---|
| 独立游戏开发者 | 快速得到角色、道具、UI 图标 | 降低美术门槛，快速验证玩法 |
| Game Jam 团队 | 短时间内批量产出素材 | 快速生成统一风格素材包 |
| 美术外包团队 | 根据需求稿快速出草图 | 提升前期方案探索效率 |
| 游戏教育用户 | 学习素材拆解与资产规范 | 通过可视化流程理解游戏资产生产 |

## 4. 产品目标

### 4.1 MVP 目标

- 支持用户输入素材需求并选择素材类型。
- 支持 Agent 自动生成结构化素材规格。
- 支持生成角色精灵、动作序列、道具图标、场景元素四类资产。
- 支持历史任务查看、生成进度查看、结果预览、局部重试和整包下载。
- 支持透明 PNG 与 Sprite Sheet 导出。
- 支持用户对生成结果进行“保持风格继续生成”“调整动作”“更换配色”等自然语言迭代。

### 4.2 非目标

- MVP 不做完整游戏引擎编辑器。
- MVP 不做多人协作和权限体系。
- MVP 不承诺所有生成结果达到商用美术终稿质量。
- LLM API 厂商暂不确定，PRD 与技术文档中仅预留接口。

## 5. 核心场景

### 5.1 角色精灵生成

用户输入：

```text
生成一个像素风猫咪勇者，蓝色斗篷，32x32，正面站立，透明背景。
```

系统输出：

- 结构化素材规格：类型、尺寸、风格、角色设定、配色、背景、导出格式。
- 生成结果：若干候选角色图。
- 操作：选中、放大预览、重试、继续生成动作。

### 5.2 动作序列生成

用户选择一个角色后输入：

```text
基于这个角色生成 idle、run、attack 三组动作，每组 6 帧。
```

系统输出：

- 动作清单与帧数计划。
- 每组动作的帧序列。
- Sprite Sheet 与 JSON 元数据。
- 一致性检查提示：角色轮廓、颜色、道具是否偏移。

### 5.3 道具与图标生成

用户输入：

```text
生成 12 个像素风地牢道具图标，包含药水、钥匙、金币、宝箱，16x16。
```

系统输出：

- 批量任务拆解。
- 统一风格的图标集合。
- 单个图标重新生成。
- ZIP 导出。

### 5.4 场景素材生成

用户输入：

```text
生成横版平台游戏森林关卡素材，包括草地地块、树、石头、背景灌木，像素风。
```

系统输出：

- Tile / Prop 分类。
- 分层预览。
- 透明 PNG 导出。

## 6. 功能需求

### 6.1 需求输入与规格化

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-001 | 自然语言输入 | P0 | 用户输入生成需求 |
| R-002 | 素材类型选择 | P0 | 角色、动作序列、道具图标、场景素材 |
| R-003 | 规格表单补全 | P0 | 尺寸、风格、背景、帧数、导出格式 |
| R-004 | Agent 自动拆解 | P0 | 将需求转为结构化生成计划 |
| R-005 | 需求冲突提示 | P1 | 例如“16x16 高细节写实风”提示风险 |

### 6.2 Agent 生成流程

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-006 | 生成计划预览 | P0 | 展示 Agent 将如何生成资产 |
| R-007 | 生成任务提交 | P0 | 创建异步生成任务 |
| R-008 | 进度展示 | P0 | 展示排队、生成、后处理、完成、失败状态 |
| R-009 | 分步日志 | P1 | 展示规格解析、提示词构建、生成、检测、导出 |
| R-010 | 失败重试 | P0 | 支持单张或单组动作重试 |

### 6.3 结果预览与迭代

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-011 | 结果网格预览 | P0 | 展示生成候选图 |
| R-012 | 大图预览 | P0 | 查看单个素材细节 |
| R-013 | 动作播放预览 | P0 | 帧动画播放、速度调节 |
| R-014 | 自然语言迭代 | P0 | 基于结果继续修改 |
| R-015 | 版本对比 | P1 | 比较不同生成版本 |

### 6.4 导出

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-016 | PNG 导出 | P0 | 单张透明 PNG |
| R-017 | Sprite Sheet 导出 | P0 | 动作序列合并导出 |
| R-018 | JSON 元数据 | P0 | 记录帧坐标、动作名、帧率 |
| R-019 | ZIP 打包 | P0 | 整个任务结果打包下载 |
| R-020 | 命名规则 | P1 | 使用项目名、素材类型、版本号命名 |

### 6.5 历史与资产管理

| 编号 | 功能 | 优先级 | 说明 |
|---|---|---|---|
| R-021 | 任务历史 | P0 | 展示最近生成任务 |
| R-022 | 资产详情 | P0 | 查看生成参数、版本和下载记录 |
| R-023 | 收藏素材 | P1 | 用户标记满意结果 |
| R-024 | 项目分组 | P1 | 按游戏项目管理素材 |

## 7. 用户流程

```text
进入工作台
  ↓
输入素材需求 / 选择素材类型
  ↓
Agent 解析需求并生成规格
  ↓
用户确认或修改规格
  ↓
提交生成任务
  ↓
查看生成进度与中间状态
  ↓
预览结果
  ↓
自然语言迭代 / 单项重试 / 继续生成动作
  ↓
导出 PNG / Sprite Sheet / JSON / ZIP
```

## 8. 页面需求

### 8.1 Landing

- 强调“描述游戏素材需求 → AI 生成并支持迭代 → 获得可投入游戏制作的精灵图资产”。
- CTA：开始生成、查看示例。
- 展示角色精灵、动作序列、场景素材三类核心能力。

### 8.2 生成工作台

- 左侧：项目与历史任务。
- 中心：Prompt 输入、规格确认、生成结果画布。
- 右侧：Agent 状态、生成参数、导出面板。
- 底部或浮层：当前任务进度。

### 8.3 资产详情页

- 展示生成图、规格、版本、关联动作、导出记录。
- 支持重新生成、复制参数、继续生成动作。

## 9. Agent 角色编排

| Agent | 职责 | 输入 | 输出 |
|---|---|---|---|
| 需求解析 Agent | 将自然语言转为素材规格 | 用户 prompt、素材类型 | 结构化 AssetSpec |
| Prompt 编排 Agent | 生成图像模型提示词与负向提示词 | AssetSpec、风格模板 | ImagePrompt |
| 生成执行 Agent | 调用图像生成 / 后处理任务 | ImagePrompt、任务参数 | 图片与任务状态 |
| 一致性评估 Agent | 检查角色、风格、动作连续性 | 生成结果、AssetSpec | 评分与修复建议 |
| 导出打包 Agent | 生成 Sprite Sheet、JSON、ZIP | 素材文件、动作配置 | 可下载资源包 |

> LLM API：暂留空，后续由技术评审根据成本、效果、合规性确定。

## 12. 验收标准

- 用户可以完成一次从输入需求到下载素材包的完整流程。
- 角色精灵、动作序列、道具图标、场景素材四类 P0 能力可用。
- 生成任务状态准确，失败可重试。
- 动作序列可播放预览，Sprite Sheet 与 JSON 元数据可导出。
- Agent 的生成计划、执行状态和结果解释对用户可见。
- 前端、后端、Agent、导出链路均有自动化测试覆盖。

## 13. 关键指标

| 指标 | MVP 目标 |
|---|---|
| 首次有效生成完成率 | >= 70% |
| 任务失败可恢复率 | >= 95% |
| 用户完成导出率 | >= 50% |
| 单次任务状态可追踪率 | 100% |
| P0 流程自动化测试通过率 | 100% |

## 14. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图像生成质量不稳定 | 用户无法直接使用结果 | 增加规格校验、负向提示词、结果重试与候选图 |
| 动作序列一致性不足 | Sprite Sheet 不可用 | 引入参考图、种子固定、一致性评估节点 |
| 生成耗时过长 | 用户等待焦虑 | 异步任务、进度展示、局部结果先展示 |
| 免费模型部署成本高 | 研发环境复杂 | MVP 支持本地 ComfyUI，生产可替换三方服务 |
| LLM API 未定 | Agent 效果不稳定 | 先定义 Provider 接口，具体 API 留空 |

## 15. 开放问题

- LLM API 供应商与调用预算：暂留空。
- 图像生成模型是优先本地部署还是接入三方 API：技术评审决策。
- 是否需要用户账号与计费：MVP 暂不纳入。
- 是否需要素材版权与安全检测：建议 P1 进入合规专项。
