# 「精灵」UI / UX 改造上下文

> 状态：P0 进行中  
> 最后更新：2026-08-10  
> 本文是后续 UI / UX 设计、开发与验收的上下文基线；如与旧 Landing 或旧品牌素材冲突，以本文为准。

## 1. 产品定位

产品名：**精灵**

核心定位：**AI 2D 游戏精灵图生成工具**。用户通过描述角色、风格、姿势和动作需求，生成可用于游戏创作的 2D 角色精灵、动作序列和场景素材。

Landing 的单一目标是让用户快速理解：

```text
描述游戏素材需求
        ↓
AI 生成并支持迭代
        ↓
获得可投入游戏制作的精灵图资产
```

产品不再按通用 AI Chatbot 或泛化 Agent Workspace 表达；Landing 文案必须服务于游戏素材生成，不使用“研究报告”“文档工作流”“通用任务执行”等表述。

## 2. 已确认的设计方向

### 视觉语言

- 主主题：深色蓝紫，不使用纯黑、赛博朋克、霓虹或大面积渐变。
- 背景：深冷灰黑 `#080B14`，辅以低透明度蓝紫环境光、细网格和弧形轮廓。
- 强调色：低饱和蓝紫（如 `#94A9FF`），仅用于核心状态、连接线、CTA 和弱光晕。
- 字体：中性无衬线；标题以中等字重、负字距和大留白建立层级。
- 边框：统一使用接近 `rgba(213, 221, 255, .11)` 的低对比边框。
- 圆角：导航、面板和视觉容器采用中等圆角，不使用过度胶囊化。

### 参考视频

参考文件：`video/dribbb-mp4.mp4`（约 16.37 秒）。

视频中被吸收的 **UI / UX 语言**：

1. 页面内居中的浮动导航和分段导航胶囊。
2. Hero 的中心“核心装置”、两侧连接线路、小型节点和大弧形空间轮廓。
3. 从 Hero 向下的短叙事节奏：核心价值 → 三节点流程 → Problem → Solutions → CTA。
4. Problem 区域的左右分栏视觉，以及 Solutions 中的粒子、标题和深色能力面板。
5. 低频、缓慢的产品动效，而不是高频营销动效。

不会复制的视频元素：

- 原视频品牌、Logo、文案、业务内容和图片。
- 绿色 / 薄荷绿配色。
- 视频中不属于「精灵」产品含义的“可信计算”叙事。

## 3. Landing 当前信息架构

当前页面顺序严格对齐视频的短叙事结构，并替换为 2D 游戏素材生成语义：

1. **浮动导航**
   - 品牌：精灵
   - 导航：总览、生成流程、核心能力、开始生成
   - 行为：登录与“开始生成”沿用原有回调。

2. **Hero：中心精灵核心**
   - 核心文案：`把你的想法变成游戏精灵图。`
   - 视觉：中心蓝紫核心、连接线路、小节点、底部弧线。
   - 快捷入口：角色精灵、动作序列、场景素材。

3. **生成流程**
   - 描述角色：定义风格、姿势与规格。
   - 生成与迭代：将灵感转成像素级素材。
   - 导出与使用：将精灵图带入游戏。

4. **创作阻力（Problem）**
   - 表达素材生产效率与沟通成本问题。
   - 使用左右分栏和中心“素材断层”节点，保留参考视频的构图逻辑。

5. **精灵生成引擎（Solutions）**
   - 风格始终一致。
   - 动作自然延展。
   - 素材立即可用。

6. **Final CTA 与极简 Footer**
   - CTA：`把下一个游戏角色，交给精灵。`
   - Footer：`AI 2D 游戏精灵图生成工具`。

## 4. 动效与交互规则

动画库：项目已安装并复用 `framer-motion`，**不需要新增动画依赖**。

已实现：

- 首屏导航：向下轻微位移 + 淡入；滚动时分段导航高亮跟随当前区块。
- Hero 核心：缩放淡入、低频呼吸光效、内部扫描光带。
- Hero 连线：节点脉冲，左右光点沿线路低频行进。
- Hero 文案、入口：分层淡入，使用轻微模糊消退；底部弧线缓慢呼吸。
- 生成流程：三节点错落入场，连接线淡入并带轻量流动感。
- Problem：两侧光球呼吸，中心“素材断层”周围浮动阻力标签。
- Solutions：四角径向粒子低频漂移；能力列表自动轮播激活态，中部指示点可点击切换。
- 按钮与入口卡片：轻微上移 Hover 反馈。
- Final CTA：滚入视口后模糊消退显现。

约束：

- 所有动效必须表达“生成中、连接中、逐步完成”，不做无意义的装饰动画。
- 支持 `prefers-reduced-motion`；减少动态偏好下动画时长接近零。
- 不使用 Scroll Hijacking、WebGL、粒子满屏、明显 3D Tilt 或高频闪烁。

## 5. 业务与技术边界

本次 P0 改造只允许调整展示层：

- UI、布局、视觉层级、文案、动效、Hover 与滚动反馈。
- 不修改 API、数据库、Store 数据结构、路由语义或业务字段。
- 不修改登录、创建作品、创建脚本等现有事件逻辑。

Landing 的按钮继续使用既有行为：

## 7. 滚动与响应式约束

项目历史根文档使用 `overflow: hidden`，旧 Landing 依赖全屏翻页组件。当前 Landing 已改为自身负责滚动：

```css
.video-landing {
  height: 100dvh;
  overflow-y: auto;
  overflow-x: hidden;
}
```

因此必须保持：

- 桌面端可使用鼠标滚轮与触控板滚动。
- 移动端可触摸滚动。
- 不依赖 `@fullpage/react-fullpage` 或 Scroll Hijacking。
- 小屏幕下隐藏中部导航，将三节点流程改为纵向排列，Problem 改为上下布局。

## 8. 品牌清理原则

Landing 与移动 Landing 的旧“爆文猫”展示组件已删除。

仍可能存在于项目其他区域的旧品牌文本、域名、历史协议、埋点标识和静态资源，不应被机械替换：

- 法律协议需要运营 / 法务确认后才能更新。
- 域名、API、数据库、环境变量、埋点事件属于技术标识，不属于 UI 改造范围。
- 其他工作区页面的可见品牌盘点仍是 P0 的待办项。
